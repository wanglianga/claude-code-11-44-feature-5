# 冷链温控接入协议说明

本文件定义两类设备上报协议、集中解析规则、时钟映射模型、质量发布与消费协议。
所有报文均为**虚构示例**，由本地发送器（`sender/`）按可控顺序发出，不依赖真实硬件。

架构决策：**集中解析**。发送器只无损转发字节/报文；组帧、校验、单位换算、
时钟映射全部在中心按**版本化协议契约**完成。新固件没有明确契约时，报文保留为
`pending_contract`（待解析），系统不凭字段形状猜测单位。

---

## 1. JSON 实时报文协议（探头直报）

每条报文是一个独立 JSON 对象，经 HTTP 提交即为一个原始信封，无组帧概念。

### 1.1 固件 2.3.x（契约 `json-temp` r1+ 的规则 `2.3`/`default`）

| 字段 | 含义 |
| --- | --- |
| `type` | 报文类型，固定 `"temp"` |
| `fw` | 固件版本，契约按它精确匹配（`"2.3.0"` / `"2.3.1"`） |
| `dev` | 设备号（探头序列号），如 `PRB-1001` |
| `boot` | 启动批次标识，如 `B7` |
| `seq` | 样本序号（启动批次内单调） |
| `evt` | 外部事件号（设备侧事件流水，仅存档） |
| `ts` | 采样时间，**必须带明确时区**的 ISO-8601 |
| `c` | 温度，**摄氏小数** |

虚构报文：

```json
{"type":"temp","fw":"2.3.1","dev":"PRB-1001","boot":"B7","seq":2,
 "evt":"EVT-9002","ts":"2026-11-15T18:10:00+08:00","c":4.6}
```

`ts` 带 `+08:00`，中心换算为 UTC `2026-11-15T10:10:00Z`，时钟误差按契约取 5s。

### 1.2 固件 3.0.x（契约 `json-temp` r2 的规则 `3.0`）

固件升级改变了**温度单位**与**设备序号含义**：

| 字段 | 含义 |
| --- | --- |
| `fw` | `"3.0.0"` |
| `asset` | **资产号**（新序号体系），契约 `device_map` 映射回探头：`A-1001 → PRB-1001` |
| `f` | 温度，**华氏度小数** |
| 其余 | `boot` / `seq` / `evt` / `ts` 同 2.3.x |

虚构报文：

```json
{"type":"temp","fw":"3.0.0","asset":"A-1001","boot":"B7","seq":4,
 "evt":"EVT-9104","ts":"2026-11-15T10:20:00+00:00","f":41.0}
```

换算：`(41.0 − 32) × 5/9 = 5.0 °C`。在契约 r2 生效前，这类报文保持待解析。

### 1.3 幂等

幂等标识 = `(规范设备号, 启动批次, 样本序号)`，载荷哈希 = 报文规范 JSON 的 SHA-256。

- 同标识同载荷 → `parsed_dup`，不增样本；
- 同标识不同载荷 → `conflict`，**保留原值**，不允许最后到达者覆盖。

## 2. 二进制离线记录仪协议 v1（契约 `bin-temp` r1）

离线记录仪缓存样本，换车/回场后经网关补传，一次连接可传来**半帧、多帧或噪声**。

### 2.1 帧布局（小端）

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | MAGIC | u8 | 固定 `0xC7` |
| 1 | VERSION | u8 | 协议/固件版本，当前 `0x01` |
| 2 | FLAGS | u8 | 保留，置 0 |
| 3 | LEN | u8 | 载荷字节数（v1 固定 10），>64 或 0 视为非法 |
| 4.. | 载荷 | — | 见 2.2 |
| 末尾 | CRC | u16le | CRC16-CCITT（多项式 0x1021，初值 0xFFFF），覆盖字节 0..载荷末尾 |

### 2.2 载荷（10 字节）

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 4 | `device_no` | u16le | 设备序号，**含义由契约设备映射表决定**：`2002 → PRB-2002`、`3003 → PRB-3003` |
| 6 | `boot_batch` | u16le | 启动批次，每次重启 +1 |
| 8 | `seq` | u16le | 设备本地计数（样本序号），**重启后从头开始** |
| 10 | `temp_raw` | i16le | 带符号定点温度 |
| 12 | `uptime_s` | u16le | 开机秒数（存档字段） |

完整帧 16 字节。虚构帧（`device_no=2002, boot=1, seq=150, temp_raw=80, uptime=4500`）：

```
C7 01 00 0A  D2 07 01 00  96 00 50 00  8A 11  B4 3D
│  │  │  │   │           │           │        └ CRC16 = 0x3DB4
│  │  │  │   │           │           └ uptime_s = 4500
│  │  │  │   │           └ seq = 150
│  │  │  │   └ device_no = 2002, boot_batch = 1
│  │  │  └ LEN = 10
│  │  └ VERSION = 1
└ MAGIC
```

（CRC 值以发送器 `frames.py` 实算为准，此处为排版示意。）

### 2.3 温度换算（契约规则）

```
v_scaled = temp_raw × 0.0625 + 0        # 定点解码，单位 °C
v_std    = v_scaled × 1.0 + (−0.2)      # 探头校准
```

例：`temp_raw=80 → 5.0 → 4.8 °C`；`temp_raw=−56 → −3.5 → −3.7 °C`（负温）。
换算每一步（raw / scale / unit / calibration / validate）都写入读数的
`conversion.steps`，界面可下钻。标准值落在物理区间 [−60, 100]°C 之外时标记
`out_of_range`——**校验始终执行**，不因数值"看起来合理"而跳过，也不静默丢弃。

### 2.4 组帧规则（按连接维护状态）

- **半帧**：字节不足一帧时缓冲等待后续块；连接关闭仍不足 → 记 `truncated`（截断）。
- **多帧**：一个块内依次解出多帧。
- **坏校验**：记 `bad_crc`（帧内声明 CRC 与实算不符），随后**只前进一个字节**
  重新扫描魔数——坏帧不能吞掉后面的完整帧；坏帧残余字节按噪声记录。
- **非法长度**：记 `bad_length`，前进一个字节。
- **噪声**：魔数前的字节记 `garbage`。
- **连接隔离**：组帧状态（缓冲 + 绝对偏移）按 `(传输批次, 连接标识)` 保存，
  不同连接的残片绝不串接；状态落库，服务重启不丢。

### 2.5 时钟映射（离线计数 → 采样时间）

只允许用**同一设备、同一启动批次**的可信锚点（`clock_anchor`）：

| 情形 | 映射 | 误差 |
| --- | --- | --- |
| 命中锚点 | 锚点时间 | 锚点误差 |
| 两锚点夹住 | 线性插值 | max(两锚点误差) + 距最近锚点步数 × 每步漂移 |
| 单侧外推 | 最近锚点 ± 步数 × 标称间隔（契约 30s） | 锚点误差 + 步数 × 每步漂移（0.05s） |
| 无锚点 | **不猜**，保持 `pending_anchor` | — |

重启后序号从头开始：新启动批次是新的幂等键空间，**不算重复**；
新批次需要自己的锚点才能映射时间。

### 2.6 归属（采样时间 × 安装区间）

读数按 `采样时间 ± 误差` 窗口与设备安装区间（探头→车辆/周转箱/货物批次，
左闭右开）连接，**不按接收时的车辆**：

- 窗口完整落入唯一区间 → 归属该区间（换车后补传的旧样本仍挂旧车）；
- 窗口跨过区间边界（如换车时刻）→ 保持 `pending_attribution`；
- 同一探头同一时刻只允许一段有效区间（录入时拒绝重叠），
  一条物理读数不会被当成多个独立观测。

## 3. 协议契约与重放

契约按 `(contract_key, revision)` 版本化，内容包括：适用固件范围
（`match`）、字段含义、设备映射、单位与换算规则、时钟规则。

- 激活新修订时，同 key 旧修订转为 `retired`；
- **重放只处理依赖该契约的原始信封**：曾用本契约任一修订解析的信封/帧，
  以及因无契约而待解析、现被新修订覆盖的信封/帧；
- 重放产出的完整新结果先挂在运行上，**校验通过后一次性切换当前索引**；
- 提交前校验：逐条独立复算一致；安装关系版本、信封水位（新固件可能到达）、
  契约修订均未漂移——任一不满足则中止，不发布"时间正确而归属过期"的信号。

## 4. 质量发布与消费协议

发布是按用途生成的**完整快照版本**：

| 用途 | 交付门槛 |
| --- | --- |
| `line_monitor` | 有可信采样时间，误差 ≤ 900s（归属可选） |
| `batch_audit` | 误差 ≤ 300s，且车辆/周转箱/货物批次归属完整 |

两者都要求换算校验 `ok`（`out_of_range` 与缺锚样本不交付）。

消费端按**游标**读取：

1. `pull` 返回当前版本的一页并记为**未确认分页**；
2. 未确认时重复 `pull` → **原样重发同一页**（失败恢复不跳过、重复拉取不产生重复样本）；
3. `ack(version, from, to)` 与未确认分页一致才推进游标，并落一条消费记录
   （重复确认幂等）；
4. 一页不漏地读完一个版本后，才进入下一个当前版本。

## 5. 本地发送器场景（可控顺序）

```bash
python sender.py run binary-main        # 半帧拼合、多帧同块、坏校验、负温、
                                        # 换车边界待归属、超量程、断连截断
python sender.py run binary-restart     # 重启后序号从头开始 + 缺锚点设备
python sender.py run json-basic         # 明确时区、重发去重、载荷冲突
python sender.py run json-new-firmware  # 新固件无契约 → 待解析
python sender.py run contract-revision  # 发布契约 r2 并重放
python sender.py run all                # 以上全部按序执行
python sender.py publish                # 构建两个用途的发布版本
python sender.py consume audit-app batch_audit  # 模拟消费端按游标读完整版本
```
